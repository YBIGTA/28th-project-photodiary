## 1. 문제 정의

> “아 이 날에 내가 뭐했더라...?”
”즐거웠던 추억 사진을 다시 찾아 보고 싶은데... 어디있지...?”
> 
- 사진은 많이 찍는데, 원하는 사진을 다시 찾아보기가 힘듦.
    - 아무리 앨범 단위로 정리해도, **과거의 특정 순간**과 관련된 사진을 빠르게 찾기 어려움.
    - ex. 옛날에 먹은 개쩌는 케이크 사진을 친구에게 보여주고 싶은데,
    이 사건이 언제 발생했는지 알지 못하면 찾기 힘들다…
- 우리는 보통 일기를 쓰지 않는다. 왜? 쓰는 것이 번거롭고 오래 걸리니까.
    - 그래서 과거에 특정 시점에서 내가 무엇을 했는지 기억이 잘 안 남.
    - 간단하게 나열식으로라도 하루를 텍스트로 정리하면 추후에 복기하기 쉬움.
- 사진 앱은 날짜별/앨범별 정리가 가능하지만, 그날의 이야기(장소 이동, 주요 이벤트, 사진 근거) 로 회고/검색하기 어려움.

→ 사용자 사진 및 위치 기반으로 자동으로 간단한 일기를 매일 생성하고, RAG 기반 검색 기능을 통해 사진과 일기를 쉽게 찾도록 한다.

## 2. 주요 기능

사용자 쿼리를 받아 관련 사진을 검색하여 제시하는 RAG 기반 챗봇 웹 서비스

## 3. 서비스 구동 예시

**Input 1**:

- 하루 동안 사용자가 촬영한 사진 이미지들
- 각 사진에 포함된 EXIF 메타데이터
    - 촬영 시간 (timestamp)
    - GPS 좌표 (위도/경도)

**Input 2**: 사용자 쿼리

**Output:** 사용자의 요청에 맞는 사진을 제시

```bash
INPUT = "지난달에 친구랑 갔던 파스타 맛집 사진 찾아줘"

OUTPUT_EXAMPLE =
"
지난달 합정에서 친구들과 파스타를 먹었던 기록이 있습니다.

[2026-01-12 | 합정동 레스토랑]
- 합정의 레스토랑에서 친구들과 파스타와 와인으로 저녁 식사를 함.
- 관련 사진: p_0202, p_0205, p_0210
"
# 실제로는 사진 ID만 출력하지 않고, 사진 이미지를 반환.
```

## 4. 필요한 데이터셋

학습 데이터: 필요 없음
(학습 진행하지 않음)

1. **시현용 사용자 데이터**: 팀원들의 실제 사진 갤러리 + EXIF
    - EXIF: 사진의 메타데이터 (날짜, 시간, 촬영)
2. **구글맵 지도 API를 통한 GPS Geocoding 데이터**: 사진의 위치 좌표 메타데이터를 의미있는 장소 관련 정보로 변환
    - Reverse Geocoding API 사용 ([네이버 지도 API](https://api.ncloud-docs.com/docs/ai-naver-mapsreversegeocoding-gc))
    - ex. (latitude, longitude) = (37.5563, 126.9237) → “마포구 연남동”
3. **RAM++ (Recognize Anything Plus Plus)**: 사진 데이터에서 사물/행동/장소 키워드 태그 추출
4. **Moondream 2 (Vision Language Model)**: 사진의 전반적인 분위기와 행동을 묘사하는 자연어 캡션 생성

## 5. 전체 파이프라인

### **Data Ingestion & Processing**

1. 사용자가 촬영한 사진을 서비스에 파일 형태로 업로드한다.
    - **Endpoint:** `POST /api/photos/upload` ([upload.py])
    - **Function:** `upload_photo`
    - 사진은 GPS 태그가 포함되어 있어야 한다.
2. 사용자의 사진을 입력으로 받으면, 메타데이터에서 촬영 시간과 GPS 좌표를 추출한다.
    - **Module:** [exif_reader.py]
    - **Functions:** `get_exif_data`, `get_lat_lon`, `get_taken_at`
3. GPS 좌표는 Geocoding API를 사용하여 의미 있는 장소 정보(동/구/POI)로 변환한다.
    - **Module:** [geocoder.py]
    - **Function:** `reverse_geocode` (Naver Maps API 활용)
4. S3 업로드 및 메타데이터 저장
    - 사진 파일은 AWS S3에 저장된다. ([s3_uploader.py] - `upload_to_s3`)
    - 추출된 메타데이터(시간, 장소, S3 Key)는 PostgreSQL에 저장된다. ([crud.py] - `insert_photo`)
5. 이벤트 클러스터링
    - **Module:** [03_clustering.py]
    - **Function:** `cluster_events`
    - **시간 기반 분할**: 이전 사진과 **2시간(120분)** 이상 차이가 나면 새 이벤트로 분리.
    - **거리 기반 분할**: **Anchor(이벤트 시작점)** 기준으로 **500m** 이상 이동 시 무조건 새 이벤트로 분리.
    - **체류(Stay) 판정**: Anchor 반경 **50m** 이내에 머무르는 경우 '체류'로 판단하여, 시간 임계값을 **12시간(720분)**으로 지정.

### **Feature Engineering**

**Image Analysis & Embedding Generation**

1. **RAM++ 태그 추출**:
    - **Module:** [02_tagging.py]
    - **Function:** `extract_tags_batch`
    - 사진에서 4500여 개의 태그 중 신뢰도가 높은 키워드를 추출하여 DB에 저장한다. (`photo_keywords` 테이블)
2. **Moondream 2 캡션 생성**:
    - **Module:** [02_tagging.py]
    - **Function:** `generate_captions_batch`
    - 사진을 보고 "남자가 식당에서 피자를 먹고 있다"와 같은 자연어 설명을 생성한다.
    - 단순 키워드(태그)로는 알 수 없는 문맥(Context), 분위기, 행동의 인과관계를 설명하여 검색 저항성을 높인다.
3. **통합 임베딩 생성 (e5-base)**: 
    - **Module:** [04_embedding.py](file:///Users/ilop0/28th-project-photodiary/pipeline/steps/04_embedding.py)
    - **Function:** `embed_photo`
    - `태그` + `캡션` + `장소/시간 메타데이터`를 결합하여 `intfloat/multilingual-e5-base` 모델로 768차원 벡터로 변환, `photo_embeddings` 테이블에 저장한다.
    - 검색 시, 사용자의 질문도 같은 모델로 벡터화하여 코사인 유사도로 가장 관련성 높은 사진을 찾는다.

    **키워드 분류 예시**

    **1. 활동 (Activity)**

    *모델이 포착한 사물과 장소의 조합으로 추론되거나, 특정 동작 태그로 추출되는 키워드*

    - **예시:** 식사, 산책, 운동, 업무(미팅), 쇼핑, 드라이브, 캠핑, 여행, 데이트, 휴식, 공연 관람, 카페 투어, 요리, 독서

    **2. 장소 (Place)**

    *Reverse Geocoding을 통해 얻은 POI 정보와 이미지의 배경(Scene) 분석을 통해 결정되는 키워드*

    - **예시:** 카페, 레스토랑, 공원, 사무실, 헬스장, 백화점, 해변, 산, 집(실내), 영화관, 전시장, 학교, 공항, 기차역

    **3. 사물 (Object)**

    *RAM++와 같은 객체 탐지 모델이 사진 속에서 직접 찾아낼 수 있는 구체적인 물체*

    - **예시:** 커피, 케이크, 노트북, 스마트폰, 키보드, 운동화, 아령, 가방, 쇼핑백, 텐트, 모닥불, 와인잔, 책, 꽃다발, 반려동물

    **4. 인물 (Person)** 
    *특정 개인을 식별하지 못하더라도, 사진의 분위기나 인원수, 구도를 통해 파악 가능한 키워드*
        
    - **예시:** 남자, 여자, 아이, 노인, 학생, 선생, 의사, 간호사
        
4. LLM을 이용하여 하나의 이벤트에 속한 사진들에서 사진별 중요도를 매긴다. <TODO> (일단은 구현하지 않음, 나중에 필요 시 구현)


### Agent Routing

1. 사용자 쿼리의 의도 분류 및 파라미터 추출
    - **Module:** [agent_router.py]
    - **Function:** `AgentRouter.classify` (GPT-4o 기반)
    - **Intents:**
        - `PHOTO_SEARCH`: 특정 조건의 사진 검색
        - `EVENT_RECALL`: 과거 경험 회상 및 내러티브 요청
        - `DIARY`: 일기 생성(`create`) 또는 조회(`retrieve`)
        - `GENERAL`: 일반적인 인사 및 안내
2. 해당 질문을 담당하는 핸들러로 라우팅한다. ([rag_engine.py])

### **RAG Interaction**

1. Retrieval (하이브리드 검색)
    - **Functions:** `search_photos_filtered`, `search_photos` ([crud.py])
    - SQL을 통한 메타데이터(날짜, 장소) 필터링과 pgvector를 이용한 코사인 유사도 검색을 병행한다.
2. Context 구성 및 답변 생성
    - **Module:** [llm.py]
    - **Function:** `generate_response` (gpt-4o-mini 기반)
    - 검색된 사진들의 메타데이터와 캡션을 LLM에 전달하여 검색 의도에 맞는 답변을 생성한다.
