# Phase 2 (통합 & 개선) 팀원별 세부 업무 분장

본 문서는 Phase 2의 목표인 **"End-to-End 파이프라인 작동"**을 달성하기 위해 각 팀원이 수행해야 할 구체적인 업무와 구현 방향을 기술합니다.

---

## 👨‍💻 Person 1: 장주원 (Data Ingestion)

**핵심 과제: 사진 업로드 및 데이터 전처리 파이프라인 구축**

현재 우리 서비스는 웹 기반이지만, 실제 사용자 시나리오(모바일 환경 등)를 고려한 데이터 수집 방식을 설계해야 합니다.

### 할 일 (To-Do)
1.  **Ingestion 정책 수립 및 구현**:
    *   **Bulk Upload vs Stream**: 웹 환경 특성상 사용자가 수동으로 사진을 여러 장 선택하여 **일괄 업로드(Bulk Upload)**하는 방식이 우선적으로 구현되어야 합니다. (추후 실시간 동기화 고려)
    *   **구현 위치**: `pipeline/steps/01_ingestion.py` (Skeleton Code 존재)
2.  **GPS 데이터 검증 강화**:
    *   **GPS 필수 정책**: 우리 서비스의 핵심인 '지도 기반 일기' 기능을 위해 GPS가 없는 사진은 원칙적으로 배제하거나 경고를 띄워야 합니다.
    *   `pipeline/utils/exif_reader.py`를 활용하여 업로드 시점에 GPS 유무를 즉시 확인하고, GPS가 없는 사진에 대해 사용자에게 **Warning** 메시지를 주거나 저장을 거부하는 로직을 추가해 주세요.
3.  **파일 처리**:
    *   업로드된 파일을 서버의 특정 디렉토리(`data/uploads`)에 저장하고 DB `photos` 테이블에 경로를 기록하는 로직을 완성해 주세요.

## 👨‍💻 Person 2: 최재형 (Agent Routing)

**핵심 과제: 사용자 의도 분석 및 Multi-Agent 라우팅 시스템 구현**

사용자의 질문을 분석하여 가장 적합한 검색/생성 에이전트에게 연결해주는 "두뇌" 역할을 만들어야 합니다.

### 할 일 (To-Do)
1.  **Agent 카테고리 재정의**:
    *   현재의 `SEARCH / DIARY / SUMMARY / GENERAL` 분류를 재검토해 주세요. 사용자가 실제로 챗봇에게 물어볼 패턴을 상상해보고, 더 세분화하거나 통합할 필요가 있는지 고민이 필요합니다.
    *   *예시 고민: "뉴욕 여행 어땠어?"는 SEARCH인가 SUMMARY인가? "맛집 추천해줘"는 기능 범위 내인가?*
2.  **Router 구현**:
    *   **구현 위치**: `backend/services/agent_router.py` (Skeleton Code 존재)
    *   LLM(GPT-4 등)을 사용하여 사용자 입력(`query`)을 받아 사전에 정의된 카테고리(Intent) 중 하나로 분류하는 로직을 작성해 주세요.
3.  **Mini-Agent 설계**:
    *   단순 분류를 넘어, 각 카테고리별로 필요한 파라미터(예: 날짜, 장소, 키워드)를 추출하는 프롬프트를 설계해 주세요.

## 👨‍💻 Person 3: 임예찬 (DB Retrieval & Hybrid Search)

**핵심 과제: 메타데이터 필터링 및 하이브리드 검색 구현**

단순한 벡터 유사도 검색을 넘어, SQL의 강력한 필터링 기능을 결합하여 검색 정확도를 높여야 합니다.

### 할 일 (To-Do)
1.  **Hybrid Search 구현**:
    *   **구현 위치**: `db/crud.py` 내 `search_photos_filtered` 함수 (Skeleton Code 존재, 기능 보강 필요)
    *   사용자 질의에서 추출된 "시간(Date)"과 "장소(Location)" 조건이 있을 경우, 이를 `WHERE` 절로 먼저 필터링한 후 벡터 검색을 수행하도록 만듭니다.
    *   *예: "작년 부산 여행 사진" → `WHERE city='부산' AND year=2025` 필터링 후 → 벡터 검색*
2.  **Dynamic Querying**:
    *   조건이 '키워드'만 있을 때, '장소'만 있을 때, '둘 다' 있을 때를 구분하여 SQL을 동적으로 생성하는 로직을 구현해 주세요.
